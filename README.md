# The Daily Web

מערכת לניהול, עריכה ופרסום חדשות. פרויקט מסכם בקורס פיתוח אפליקציות אינטרנטיות.

Node.js · Express · MongoDB/Mongoose · EJS · Vanilla JS (Ajax)

## התקנה והרצה

דרישות: Node.js 20 ומעלה, ו-MongoDB שרץ מקומית (או חיבור ל-MongoDB Atlas).

```bash
npm install
cp .env.example .env      # ולמלא את הערכים
npm run seed              # מוחק את כל הנתונים ויוצר נתוני דמה (500 כתבות, היסטוריית צפיות ועדכונים)
npm run dev               # מריץ עם טעינה מחדש אוטומטית
npm test                  # בדיקות אוטומטיות (מריץ seed, ולכן מוחק את הנתונים!)
```

האתר יעלה בכתובת http://localhost:3000

משתמשי דמה:

| תפקיד | שם משתמש | סיסמה |
|---|---|---|
| עורך | `editor` | `editor123` |
| כתב | `reporter1`, `reporter2`, `reporter3` | `reporter123` |

## מבנה הפרויקט

```
app.js                  נקודת הכניסה: הגדרות, sessions, חיבור ה-routes
config/                 חיבור ל-DB, לוגר, קבועים משותפים (סטטוסים, קטגוריות)
models/                 סכמות Mongoose
  Article.js            משותף: draft + published (ראו הסבר למטה)
  User.js  Comment.js  ViewStat.js  DeviceView.js
controllers/            הלוגיקה של כל אזור
routes/                 קובץ routes לכל אזור
middleware/             הרשאות, מזהה מכשיר, הגבלת תגובות, טיפול בשגיאות
services/               לוגיקה משותפת: מעברי מצב, צפיות, מזג אוויר
views/                  תבניות EJS, תיקייה לכל אזור + partials משותפים
public/                 CSS ו-JS של צד הלקוח (vendor/chart.umd.js: ספריית Chart.js 4.4.1 לגרף)
seed/                   נתוני דמה: seed.js (משתמשים, כתבות, תגובות), seedViews.js (צפיות והיסטוריית פרסום), seedUpdates.js (עדכונים ממתינים)

logs/                   קובץ לוג (לא עולה לגיט)
```

## איך בנויה כתבה

לכל כתבה יש שתי גרסאות של תוכן:

- `published`: מה שהציבור רואה. ריק (`null`) עד האישור הראשון.
- `draft`: מה שהכתב עובד עליו (נשמר אוטומטית). כשעורך מאשר, הגרסה מועתקת ל-`published`.

האתר הציבורי תמיד שולף כתבות לפי `published != null` ומציג את `published.*`, בלי קשר ל-`status`. ככה הגרסה הקודמת ממשיכה להופיע כל עוד עדכון ממתין לאישור.

מעברי מצב מותרים (מוגדרים ב-`services/articleService.js`, והשרת חוסם כל מעבר אחר):

| מ- | אל | מי |
|---|---|---|
| בהכנה (`draft`) | ממתינה (`pending`) | כתב |
| הוחזרה (`returned`) | ממתינה (`pending`) | כתב |
| ממתינה (`pending`) | פורסמה (`published`) | עורך |
| ממתינה (`pending`) | הוחזרה (`returned`) + הערה | עורך |
| פורסמה (`published`) | ממתינה (`pending`) | כתב (הגשת עדכון לכתבה שפורסמה, ראו "אזור כתב") |

## API

כל ה-API מחזיר JSON. שגיאות מוחזרות בפורמט `{ "error": "הודעה בעברית" }`.

| Method | Path | תיאור | בעלים |
|---|---|---|---|
| GET | `/api/articles?page=&q=&category=&viewed=&sort=` | פיד. מחזיר `{ articles, hasMore }` | 1 |
| GET | `/api/weather` | מזג אוויר (cache של 15 דקות) | 1 |
| POST | `/auth/login` · `/auth/logout` | התחברות והתנתקות | 2 |
| GET/POST | `/api/comments/:articleId` | רשימת תגובות / הוספת תגובה (עד 3 בדקה) | 2 |
| PUT/DELETE | `/api/comments/:id` | עריכה ומחיקה (עורך) | 2 |
| GET/POST/PUT/DELETE | `/api/users[/:id]` | ניהול משתמשים (עורך) | 2 |
| GET/POST | `/reporter/api/articles?page=` | הכתבות שלי (`{ articles, hasMore }`) / יצירת כתבה `{ category, title? }` | 3 |
| PUT | `/reporter/api/articles/:id/draft` | שמירה אוטומטית של הטיוטה | 3 |
| POST | `/reporter/api/articles/:id/submit` | הגשה לאישור (גם הגשת עדכון לכתבה שפורסמה) | 3 |
| POST | `/reporter/api/articles/:id/discard` | ביטול שינויים בכתבה שפורסמה (הטיוטה חוזרת להיות הגרסה המפורסמת) | 3 |
| GET | `/editor/api/articles?status=&q=&page=` | כל הכתבות עם מספרים לפי מצב. מחזיר `{ articles, counts, hasMore }` | 4 |
| PUT | `/editor/api/articles/:id/draft` | עריכה על ידי העורך | 4 |
| POST | `/editor/api/articles/:id/approve` | אישור ופרסום | 4 |

# ...עבודה, commits קטנים עם הודעות ברורות...

# פותחים Pull Request, חבר אחר עובר ומאשר, ואז merge

## פיצ'רים

### אזור עורך, ספירת צפיות ו-Impact Analytics (חבר 4)

- **ספירת צפיות**: כל כניסה לכתבה מוסיפה 1 למונה של אותה כתבה באותה שעה (`ViewStat`: כתבה, תחילת השעה, `count`) ול-`Article.viewCount`. זה עדכון אטומי אחד (`$inc` עם `upsert`), ואינדקס ייחודי על (כתבה, שעה) מונע כפילויות. כך אלפי קוראים במקביל לא יוצרים מסמך לכל צפייה, והגרף קורא רק כמה עשרות מסמכים קטנים.
- **דשבורד עורך** (`/editor`): כל הכתבות עם סינון לפי מצב ומספרים, "טען עוד", ללא רענון עמוד. עדכון של כתבה שכבר פורסמה מסומן "עדכון".
- **עמוד בדיקה** (`/editor/articles/:id`): התוכן שהוגש. בעדכון של כתבה שפורסמה מוצגות זו לצד זו הגרסה המפורסמת והגרסה החדשה, והשדות ששונו מסומנים. העורך יכול לערוך, לאשר ולפרסם, להחזיר לכתב עם הערה (חובה) או למחוק (נמחקים גם התגובות והסטטיסטיקות של הכתבה).
- **Impact Analytics** (`/editor/analytics`): גרף Chart.js של צפיות לאורך זמן. בכל פרסום או עדכון שאושר יש קו מקווקו (הנתונים מ-`Article.publishHistory`), ואפשר לבחור פרסום ולראות השוואה: ממוצע צפיות לשעה ב-24 השעות שלפניו ובשעות שאחריו.
- **הרשאות**: כל הנתיבים תחת `/editor` מוגנים בצד השרת (`requireRole('editor')`), כתב מקבל 403 ומשתמש לא מחובר מקבל 401 או הפניה להתחברות.
- **אבטחה**: מזהים נבדקים לפני השימוש, שדות חייבים להיות מחרוזות (מונע הזרקת אופרטורים של MongoDB), טקסט חיפוש עובר escape, והתצוגה משתמשת ב-escape של EJS וב-`textContent`.
- **נתוני דמה**: `npm run seed` יוצר 500 כתבות, 30 ימים של צפיות לפי שעה, כתבות שעודכנו כמה פעמים, וכתבות ממתינות שהן עדכון של כתבה שפורסמה.
- **בדיקות**: `npm test` מריץ 436 בדיקות אוטומטיות (תחביר, נתוני דמה, אתר ציבורי ו-SEO, ספירת צפיות במקביל, הרשאות, פעולות עורך, ניסיונות הזרקה ו-XSS, עומס, אזור הכתב ו-restart של השרת). הבדיקה מוחקת את הנתונים, לכן מריצים אותה רק על מסד נתונים לפיתוח.

### אזור כתב (חברה 3)

- **הכתבות שלי** (`/reporter`): רק הכתבות של הכתב המחובר, מהחדשה לישנה, 20 בכל טעינה ("טען עוד"). הכותב נקבע לפי ה-session בשרת ולא לפי מה שהדפדפן שולח. לכל כתבה מוצגים כותרת, קטגוריה, מצב ותאריך עדכון. כתבה שהוחזרה מציגה תצוגה מקדימה של הערת העורך, וכתבה שפורסמה מסומנת "יש שינויים שלא הוגשו" או "עדכון".
- **יצירה**: טופס קצר (קטגוריה חובה, כותרת אופציונלית) יוצר כתבה במצב "בהכנה" ומעביר לעריכה. השרת קובע את הכותב ואת המצב, וכל שדה אחר בבקשה מתעלמים ממנו.
- **עריכה ושמירה אוטומטית** (`/reporter/articles/:id/edit`): הטופס מתמלא בשרת, ולכן רענון, סגירת הדפדפן ומעבר למחשב אחר מחזירים את הגרסה האחרונה (הכול נשמר ב-MongoDB ולא ב-`localStorage`). הדפדפן שולח את הטיוטה 1.5 שניות אחרי שהכתב מפסיק להקליד, ולפחות כל 10 שניות בהקלדה רצופה. תמיד רצה בקשה אחת בלבד, וההקלדה שנוספה בזמן שהיא רצה נשלחת מיד אחריה. כשהשמירה נכשלת הטקסט נשאר בשדות והניסיון חוזר אחרי 2, 5 ואז כל 10 שניות. שגיאות שניסיון חוזר לא יתקן (נותקת, אין הרשאה, הכתבה הוגשה) עוצרות את השמירה עם הסבר. בעזיבת הדף יש התראה על שינוי שלא נשמר, ושמירה אחרונה (`keepalive`). הכפתור "שמור עכשיו" הוא תוספת בלבד. השרת מעדכן בפעולה אחת שבודקת גם בעלות ומצב, כך שבקשה ישנה לא דורסת פעולה של עורך.
- **הגשה לאישור**: כותרת ותוכן חובה. הכפתור שומר קודם את הגרסה האחרונה (ואם השמירה נכשלה לא מגישים), ואז קורא ל-`transition()`, המקום היחיד ששומר מעברי מצב. `transition()` בודק גם שכתב מזיז רק כתבה שלו, ובודק שוב את המצב בתוך השמירה עצמה: אם מישהו שינה את המצב בינתיים, שום דבר לא נכתב והמשתמש מקבל הודעה (409). אחרי ההגשה הכתב לא יכול לערוך עד שהעורך מאשר או מחזיר.
- **הערת עורך**: כשהכתבה הוחזרה, ההערה מוצגת בדשבורד ובעמוד העריכה, ואפשר לתקן ולהגיש מחדש. ההערה מוצגת רק כשהמצב הוא "הוחזרה", והתוכן עובר escape.
- **עריכת כתבה שפורסמה**: הציבור ממשיך לראות את `published` כל הזמן. הכתב עורך את `draft`, והסטטוס נשאר "פורסמה". בהגשה הכתבה עוברת `published → pending`, והעורך רואה אותה כעדכון (הגרסה המפורסמת והחדשה זו לצד זו). אישור מעתיק את הטיוטה ל-`published` ומוסיף סימון בגרף. המעבר `published → pending` אינו רשום במפורש בטבלת המעברים. הוא נובע מהדרישה שגרסה חדשה של כתבה שפורסמה "תעבור את אותו תהליך אישור" (העורך מטפל רק בכתבות במצב ממתינה), וכך הבנו את התהליך. הקטגוריה נעולה בכתבה שיש לה גרסה מפורסמת (היא שדה של הכתבה כולה, ושינוי שלה היה מופיע באתר לפני האישור). הגשה בלי שינוי נחסמת, ו"ביטול שינויים" מחזיר את הטיוטה להיות הגרסה המפורסמת.
- **הרשאות**: כל הנתיבים תחת `/reporter` מוגנים בצד השרת (`requireRole('reporter')`). כתב פותח, שומר, מגיש ומבטל שינויים רק בכתבות שלו (403 לכתבה של אחר), עורך מקבל 403 ומשתמש לא מחובר מקבל 401 או הפניה להתחברות.
- **אבטחה**: מזהים נבדקים לפני השימוש, שדות חייבים להיות מחרוזות (מונע הזרקת אופרטורים של MongoDB), רק שדות מותרים נקראים מהבקשה, קישור תמונה חייב להתחיל ב-`http` או `https`, והתצוגה משתמשת ב-escape של EJS וב-`textContent`.
- **בדיקות**: סעיפים R1 עד R9 ב-`tests/full-test.js` (פקודת `npm test`, כ-147 בדיקות) בודקים מול ה-API האמיתי: הרשימה והעימוד, יצירה, שמירה ושדות לא תקינים, הרשאות, הגשה, שילוב עם העורך והאתר הציבורי, הערות עורך, עריכת כתבה שפורסמה, restart של השרת והלוג. הבדיקה מוחקת את הנתונים, לכן מריצים אותה רק על מסד נתונים לפיתוח.
