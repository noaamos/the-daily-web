# The Daily Web

מערכת לניהול, עריכה ופרסום חדשות. פרויקט מסכם בקורס פיתוח אפליקציות אינטרנטיות.

Node.js · Express · MongoDB/Mongoose · EJS · Vanilla JS (Ajax)

## התקנה והרצה

דרישות: Node.js 20 ומעלה, ו-MongoDB שרץ מקומית (או חיבור ל-MongoDB Atlas).

```bash
npm install
cp .env.example .env      # ולמלא את הערכים
npm run seed              # מוחק את כל הנתונים ויוצר נתוני דמה (500 כתבות, תגובות, היסטוריית צפיות ועדכונים)
npm run dev               # מריץ עם טעינה מחדש אוטומטית
npm test                  # בדיקות אוטומטיות (מריץ seed, ולכן מוחק את הנתונים!)
```

האתר יעלה בכתובת http://localhost:3000

מזג האוויר דורש מפתח חינמי מ-[OpenWeatherMap](https://openweathermap.org/api) (בלי כרטיס אשראי): שמים אותו ב-`WEATHER_API_KEY` בקובץ `.env`. בלי מפתח האתר עובד כרגיל והווידג'ט מציג "מזג האוויר לא זמין כרגע".

ב-Windows שתי בדיקות ב-`npm test` נכשלות בגלל הבדלי מערכת הפעלה בבדיקה עצמה (הרצת ה-seed דרך `npm`, ובדיקת נתיבים של קוד debug). מריצים `npm run seed` לפני `npm test` כדי שהשאר ירוצו על נתונים.

## איך בנויה כתבה

לכל כתבה יש שתי גרסאות של תוכן:

- `published`: מה שהציבור רואה. ריק (`null`) עד האישור הראשון.
- `draft`: מה שהכתב עובד עליו (נשמר אוטומטית). כשעורך מאשר, הגרסה מועתקת ל-`published`.

האתר הציבורי תמיד שולף כתבות לפי `published != null` ומציג את `published.*`, בלי קשר ל-`status`. ככה הגרסה הקודמת ממשיכה להופיע כל עוד עדכון ממתין לאישור.

מעברי מצב מותרים (מוגדרים ב-`services/articleService.js`, והשרת חוסם כל מעבר אחר):

| מ- | אל | מי |
|---|---|---|
| בהכנה (`draft`) | ממתינה (`pending`) | כתב |
| הוחזרה (`returned`) | ממתינה (`pending`) | כתב |
| ממתינה (`pending`) | פורסמה (`published`) | עורך |
| ממתינה (`pending`) | הוחזרה (`returned`) + הערה | עורך |
| פורסמה (`published`) | ממתינה (`pending`) | כתב (הגשת עדכון לכתבה שפורסמה, ראו "אזור כתב") |

## פיצ'רים

### אזור עורך, ספירת צפיות ו-Impact Analytics (חבר 4)

- **ספירת צפיות**: כל כניסה לכתבה מוסיפה 1 למונה של אותה כתבה באותה שעה (`ViewStat`: כתבה, תחילת השעה, `count`) ול-`Article.viewCount`. זה עדכון אטומי אחד (`$inc` עם `upsert`), ואינדקס ייחודי על (כתבה, שעה) מונע כפילויות. כך אלפי קוראים במקביל לא יוצרים מסמך לכל צפייה, והגרף קורא רק כמה עשרות מסמכים קטנים.
- **דשבורד עורך** (`/editor`): כל הכתבות עם סינון לפי מצב ומספרים, "טען עוד", ללא רענון עמוד. עדכון של כתבה שכבר פורסמה מסומן "עדכון".
- **עמוד בדיקה** (`/editor/articles/:id`): התוכן שהוגש. בעדכון של כתבה שפורסמה מוצגות זו לצד זו הגרסה המפורסמת והגרסה החדשה, והשדות ששונו מסומנים. העורך יכול לערוך, לאשר ולפרסם, להחזיר לכתב עם הערה (חובה) או למחוק (נמחקים גם התגובות והסטטיסטיקות של הכתבה). בטופס העריכה חובה למלא כותרת ותוכן והקישור לתמונה חייב להיות תקין (אותו כלל כמו אצל הכתב, `public/js/image-link.js`): הודעה אדומה מופיעה ליד השדה הבעייתי, וגם סיבת הדחייה של השרת מוצגת ליד הכפתורים. השרת בודק את אותם כללים, ובנוסף `transition()` מסרב לפרסם כתבה בלי כותרת או בלי תוכן, בכל דרך שבה הגיעה למצב ממתינה.
- **Impact Analytics** (`/editor/analytics`): גרף Chart.js של צפיות לאורך זמן. בכל פרסום או עדכון שאושר יש קו מקווקו (הנתונים מ-`Article.publishHistory`), ואפשר לבחור פרסום ולראות השוואה: ממוצע צפיות לשעה ב-24 השעות שלפניו ובשעות שאחריו.
- **הרשאות**: כל הנתיבים תחת `/editor` מוגנים בצד השרת (`requireRole('editor')`), כתב מקבל 403 ומשתמש לא מחובר מקבל 401 או הפניה להתחברות.
- **אבטחה**: מזהים נבדקים לפני השימוש, שדות חייבים להיות מחרוזות (מונע הזרקת אופרטורים של MongoDB), טקסט חיפוש עובר escape, והתצוגה משתמשת ב-escape של EJS וב-`textContent`.
- **נתוני דמה**: `npm run seed` יוצר 500 כתבות, 30 ימים של צפיות לפי שעה, כתבות שעודכנו כמה פעמים, וכתבות ממתינות שהן עדכון של כתבה שפורסמה.
- **בדיקות**: `npm test` מריץ 436 בדיקות אוטומטיות (תחביר, נתוני דמה, אתר ציבורי ו-SEO, ספירת צפיות במקביל, הרשאות, פעולות עורך, ניסיונות הזרקה ו-XSS, עומס, אזור הכתב ו-restart של השרת). הבדיקה מוחקת את הנתונים, לכן מריצים אותה רק על מסד נתונים לפיתוח.

### אזור כתב (חברה 3)

- **הכתבות שלי** (`/reporter`): רק הכתבות של הכתב המחובר, מהחדשה לישנה, 20 בכל טעינה ("טען עוד"). הכותב נקבע לפי ה-session בשרת ולא לפי מה שהדפדפן שולח. לכל כתבה מוצגים כותרת, קטגוריה, מצב ותאריך עדכון. כתבה שהוחזרה מציגה תצוגה מקדימה של הערת העורך, וכתבה שפורסמה מסומנת "יש שינויים שלא הוגשו" או "עדכון".
- **סינון הכתבות שלי**: כפתורי סינון לפי מצב (הכל, בהכנה, הוחזרו לתיקונים, ממתינות לאישור, פורסמו), כל אחד עם מספר הכתבות במצב הזה, ותיבת סימון "פורסמו עם שינויים שלא הוגשו" (זמינה ב"הכל" וב"פורסמו"). המספרים מחושבים בשרת (`counts`) ולא משתנים בזמן סינון. הסינון נשמר בכתובת (`/reporter?status=draft&unsent=1`), ומצב לא מוכר בכתובת מתעלמים ממנו. כפתורי הסינון משותפים עם דשבורד העורך (`main.css`).
- **יצירה**: טופס קצר (קטגוריה חובה, כותרת אופציונלית) יוצר כתבה במצב "בהכנה" ומעביר לעריכה. השרת קובע את הכותב ואת המצב, וכל שדה אחר בבקשה מתעלמים ממנו.
- **עריכה ושמירה אוטומטית** (`/reporter/articles/:id/edit`): הטופס מתמלא בשרת, ולכן רענון, סגירת הדפדפן ומעבר למחשב אחר מחזירים את הגרסה האחרונה (הכול נשמר ב-MongoDB ולא ב-`localStorage`). הדפדפן שולח את הטיוטה 1.5 שניות אחרי שהכתב מפסיק להקליד, ולפחות כל 10 שניות בהקלדה רצופה. תמיד רצה בקשה אחת בלבד, וההקלדה שנוספה בזמן שהיא רצה נשלחת מיד אחריה. כשהשמירה נכשלת הטקסט נשאר בשדות והניסיון חוזר אחרי 2, 5 ואז כל 10 שניות. שגיאות שניסיון חוזר לא יתקן (נותקת, אין הרשאה, הכתבה הוגשה) עוצרות את השמירה עם הסבר. בעזיבת הדף יש התראה על שינוי שלא נשמר, ושמירה אחרונה (`keepalive`). הכפתור "שמור עכשיו" הוא תוספת בלבד: הוא שומר מיד, ואם אין מה לשמור הוא מציג "הכול שמור ✓" עם השעה. השרת מעדכן בפעולה אחת שבודקת גם בעלות ומצב, כך שבקשה ישנה לא דורסת פעולה של עורך.
- **הגשה לאישור**: כותרת ותוכן חובה. הכפתור שומר קודם את הגרסה האחרונה (ואם השמירה נכשלה לא מגישים), ואז קורא ל-`transition()`, המקום היחיד ששומר מעברי מצב. `transition()` בודק גם שכתב מזיז רק כתבה שלו, ובודק שוב את המצב בתוך השמירה עצמה: אם מישהו שינה את המצב בינתיים, שום דבר לא נכתב והמשתמש מקבל הודעה (409). אחרי ההגשה הכתב לא יכול לערוך עד שהעורך מאשר או מחזיר.
- **קישור לתמונה**: מתחת לשדה מוצגת תצוגה מקדימה של התמונה (נטענת בדפדפן, אחרי שהכתב מפסיק להקליד), עם הודעה אם הקישור לא מוביל לתמונה. קישור חייב להתחיל ב-`http://` או `https://` ולכלול כתובת אתר אמיתית (לא `http://` לבד, לא `javascript:`, `data:`, `ftp:` או נתיב יחסי). כל עוד הקישור לא תקין הוא לא נשמר, כפתור ההגשה לאישור כבוי וליד הכפתורים מוצגת הסיבה. אותו כלל נבדק גם בשרת (`services/imageLink.js`, גם בשמירת טיוטה וגם בעריכה של עורך), והשרת לעולם לא פונה לקישור עצמו.
- **הערת עורך**: כשהכתבה הוחזרה, ההערה מוצגת בדשבורד ובעמוד העריכה, ואפשר לתקן ולהגיש מחדש. ההערה מוצגת רק כשהמצב הוא "הוחזרה", והתוכן עובר escape.
- **עריכת כתבה שפורסמה**: הציבור ממשיך לראות את `published` כל הזמן. הכתב עורך את `draft`, והסטטוס נשאר "פורסמה". בהגשה הכתבה עוברת `published → pending`, והעורך רואה אותה כעדכון (הגרסה המפורסמת והחדשה זו לצד זו). אישור מעתיק את הטיוטה ל-`published` ומוסיף סימון בגרף. המעבר `published → pending` אינו רשום במפורש בטבלת המעברים. הוא נובע מהדרישה שגרסה חדשה של כתבה שפורסמה "תעבור את אותו תהליך אישור" (העורך מטפל רק בכתבות במצב ממתינה), וכך הבנו את התהליך. הקטגוריה נעולה בכתבה שיש לה גרסה מפורסמת (היא שדה של הכתבה כולה, ושינוי שלה היה מופיע באתר לפני האישור). הגשה בלי שינוי נחסמת (גם כשהעורך החזיר את העדכון לתיקונים והכתב מנסה להגיש אותו שוב בלי לשנות כלום, כדי שלא יתווסף סימון עדכון מזויף לגרף), ו"ביטול שינויים" מחזיר את הטיוטה להיות הגרסה המפורסמת.
- **הרשאות**: כל הנתיבים תחת `/reporter` מוגנים בצד השרת (`requireRole('reporter')`). כתב פותח, שומר, מגיש ומבטל שינויים רק בכתבות שלו (403 לכתבה של אחר), עורך מקבל 403 ומשתמש לא מחובר מקבל 401 או הפניה להתחברות.
- **אבטחה**: מזהים נבדקים לפני השימוש, שדות חייבים להיות מחרוזות (מונע הזרקת אופרטורים של MongoDB), רק שדות מותרים נקראים מהבקשה, קישור תמונה חייב להיות כתובת `http` או `https` תקינה (`services/imageLink.js`), והתצוגה משתמשת ב-escape של EJS וב-`textContent`.
- **בדיקות**: סעיפים R1 עד R9 ב-`tests/full-test.js` (פקודת `npm test`) בודקים מול ה-API האמיתי: הרשימה והעימוד, סינון לפי מצב ושינויים שלא הוגשו, כלל קישור התמונה, יצירה, שמירה ושדות לא תקינים, הרשאות, הגשה, שילוב עם העורך והאתר הציבורי, הערות עורך, עריכת כתבה שפורסמה, restart של השרת והלוג. הבדיקה מוחקת את הנתונים, לכן מריצים אותה רק על מסד נתונים לפיתוח.

### אתר ציבורי: עמוד הבית, פיד וכתבה (חבר 1)

- **עמוד הבית** (`/`): פתוח לכולם ומציג רק כתבות שפורסמו. החלק העליון ("עמוד ראשי") נבנה בשרת מ-14 הכתבות החדשות ביותר, וכל כתבה מופיעה בו פעם אחת: קרוסלה של 4 כתבות מובילות (חיצים, נקודות, מקשי החצים, ומתחלפת לבד כל 6 שניות. נעצרת כשהעכבר או המקלדת בתוכה ולא זזה למי שביקש פחות תנועה), שתי כתבות בינוניות לצידה, שורת "כתבות נבחרות", ובסיידבר מזג אוויר, "הכי נקראות" ו"חדשות אחרונות". הקרוסלה עובדת גם בלי JavaScript (נראית הכתבה הראשונה), וכל תוכנה כבר ב-HTML שהשרת מחזיר.
- **פיד "כל הכתבות"** (`public/js/feed.js`): גלילה אינסופית, 20 כתבות בכל טעינה (`IntersectionObserver`), חיפוש לפי כותרת (מתחיל 350 מילישניות אחרי שמפסיקים להקליד), סינון לפי קטגוריה ולפי נצפה / לא נצפה, ומיון לפי תאריך פרסום או פופולריות. הכול דרך `fetch` בלי רענון עמוד, והכתובת מתעדכנת (`/?q=...&category=...`) כך שרענון, "אחורה" ושיתוף קישור שומרים את אותן תוצאות. בזמן חיפוש או בחירת קטגוריה בסרגל העליון החלק העליון של הדף (הקרוסלה והכתבות הנבחרות) מוסתר, והדף נשאר במקומו. הרשימות הנפתחות מעל "כל הכתבות" (קטגוריה, נצפה / לא נצפה, מיון) משנות רק את הרשימה ולא מסתירות אותו. כניסה ישירה לכתובת עם סינון (`/?category=sports`) מסתירה אותו כבר בשרת. בצד יש תמיד מזג אוויר, "הכי נקראות" ו"חדשות אחרונות", וגם בעמוד כתבה.
- **ללא כפילויות ובלי קפיצות**: הדף הראשון מחזיר `snapshot` (רגע הטעינה) והדפים הבאים כוללים רק כתבות שפורסמו עד אז, ולכן כתבה חדשה שמתפרסמת באמצע גלילה לא דוחפת כתבות ולא יוצרת כפילות. בחיפוש או סינון חדש הכתבות הישנות נשארות על המסך עד שהתוצאות החדשות מגיעות (תמונות הכתבות הראשונות נטענות מראש, עד 1.5 שניות), ואז מוחלפות בבת אחת בהחלפה רכה (`View Transitions`, בלי אנימציה למי שביקש פחות תנועה). רק אם התשובה איטית (יותר מ-0.4 שניות) הרשימה מעומעמת ומופיע "טוען כתבות...".
- **נצפה / לא נצפה**: כל דפדפן מקבל מזהה אנונימי בעוגייה (`dw_device`, שנה), ו-`DeviceView` שומר אילו כתבות המכשיר פתח. כתבות שנפתחו מסומנות "נקרא".
- **עמוד כתבה** (`/articles/:id`): כותרת, כתב, קטגוריה, תאריך פרסום (וזמן עדכון אחרון אם עודכנה), תמונה ותוכן מלא, **הכול ב-HTML הראשוני מהשרת** (גם `<title>`, `description` ו-Open Graph) ולכן נגיש למנועי חיפוש בלי JavaScript. התבנית משתמשת בתגיות סמנטיות (`article`, `header`, `time`, `main`, `nav`). הציבור רואה תמיד את הגרסה שפורסמה: כתבה בהכנה או ממתינה לאישור אינה נגישה (404), ועדכון שממתין לאישור לא מוצג. כל כניסה נספרת (`recordView`) בלי להאט את הדף.
- **API**: `GET /api/articles?page=&q=&category=&viewed=&sort=&snapshot=` מחזיר `{ articles, hasMore, page, snapshot }`. פרמטרים לא תקינים מחזירים 400 בעברית: `page` רק ספרות (1 עד 100000), `sort` רק מהרשימה (גם `constructor` נחסם), `snapshot` רק בפורמט שהשרת עצמו החזיר (תאריך ISO), וטקסט החיפוש בלי תווי בקרה (כמו תו null, ששובר את MongoDB) ועד 100 תווים. אותה בדיקה (`services/queryParams.js`) משמשת גם את רשימת הכתב, רשימת העורך ורשימת המשתמשים. טקסט החיפוש עובר escape כך ש-`C++` או `(` לא שוברים את השאילתה. כתובת עם `%` שבור (למשל `/articles/%E0%A4%A`) מחזירה 400 בעברית.
- **ביצועים**: אינדקסים על תאריך פרסום, קטגוריה ותאריך, מספר צפיות ומחבר, ועימוד עם `limit` ו-`skip`, כך שהפיד נשאר מהיר גם עם אלפי כתבות.

### מזג אוויר (חבר 1)

- הווידג'ט בסיידבר מציג טמפרטורה, תיאור, תחושה, לחות ורוח לעיר `WEATHER_CITY` (ברירת מחדל תל אביב), מ-OpenWeatherMap (מסלול חינמי בלי כרטיס אשראי).
- הדפדפן פונה רק לשרת שלנו (`GET /api/weather`), לעולם לא ישירות לשירות החיצוני, כך שהמפתח נשאר סודי.
- השרת מחזיק את התשובה בזיכרון ל-**15 דקות** (`WEATHER_CACHE_MS`), ולכן אלפי קוראים במקביל גורמים בערך ל-4 קריאות לשעה. כשה-cache פג והרבה קוראים מגיעים יחד, רק בקשה אחת יוצאת והשאר מחכים לאותה תשובה.
- כשהשירות החיצוני נכשל: timeout של 5 שניות, ניסיון חוזר רק אחרי דקה, והמשתמש ממשיך לראות את הנתונים האחרונים עם ההערה "ייתכן שהנתונים אינם עדכניים". הדף עצמו אף פעם לא נופל בגלל מזג האוויר. כל תקלה נרשמת בלוג.

### הזדהות, הרשאות, תגובות וניהול משתמשים (חבר 2)

- **התחברות** (`/auth/login`): שם משתמש וסיסמה לכתבים ולעורכים. הסיסמאות נשמרות רק כ-hash של bcrypt (10 סיבובים) ולא ניתן לשחזר מהן את המקור. הודעת השגיאה זהה כששם המשתמש לא קיים וכשהסיסמה שגויה. אחרי התחברות מוחלף מזהה ה-session (מונע session fixation), כתב מועבר ל-`/reporter` ועורך ל-`/editor`.
- **Sessions**: נשמרים ב-MongoDB (`connect-mongo`, 7 ימים), ולכן אחרי הפעלה מחדש של השרת משתמש מחובר ממשיך לעבוד בלי להתחבר שוב.
- **הרשאות בצד השרת בלבד**: `middleware/auth.js` טוען את המשתמש מה-session (לא ממה שהדפדפן שולח), ו-`requireRole()` מגן על כל אזור. משתמש לא מחובר מקבל 401 (או הפניה להתחברות בדפים), ותפקיד לא מתאים מקבל 403. הסתרת כפתורים בצד הלקוח היא רק נוחות.
- **תגובות** (`public/js/comments.js`): הרשימה נטענת ב-Ajax, ותגובה חדשה מתווספת מיד לסוף הרשימה בלי לטעון אותה מחדש. תגובות מותרות רק על כתבות שפורסמו, שם עד 50 תווים ותגובה עד 1000, והתצוגה משתמשת ב-`textContent`.
- **הגבלת תגובות**: אורח יכול לפרסם עד **3 תגובות בדקה מאותו מכשיר**. הבדיקה בשרת (`middleware/commentLimit.js`), לפי תגובות שכבר שמורות ב-MongoDB (ולכן גם מחזיקה אחרי restart). "אותו מכשיר" הוא עוגיית המכשיר **או** כתובת ה-IP (נשמרת בתגובה של אורח): סקריפט או דפדפן שמוחקים את העוגייה בכל בקשה עדיין נחסמים. בקשות של אותו אורח שמגיעות באותו רגע ממתינות בתור (נעילה בזיכרון השרת, לפני הספירה ועד סוף התשובה), ולכן 12 בקשות במקביל מייצרות בדיוק 3 תגובות ולא יותר. הנעילה מתאימה לתהליך שרת אחד, שזה מה שהפרויקט מריץ. חריגה מחזירה 429 עם הודעה בעברית וכמה שניות להמתין, והטקסט שהוקלד נשאר בטופס. כתבים ועורכים מחוברים אינם מוגבלים, והתגובות שלהם לא נספרות לאורחים. מחיר ההגבלה לפי IP: כמה אורחים מאחורי אותה רשת (או שני דפדפנים באותו מחשב) חולקים את אותן 3 התגובות בדקה.
- **עורך על תגובות**: עורך רואה בעמוד הכתבה כפתורי עריכה ומחיקה לכל תגובה (`PUT /api/comments/:id`, `DELETE /api/comments/:id`, עורך בלבד).
- **ניהול משתמשים** (`/editor/users`, `/api/users`, עורך בלבד): חיפוש, יצירה, עריכה ומחיקה. שם משתמש 3 עד 30 תווים באנגלית, סיסמה לפחות 6 תווים, ושם משתמש כפול מחזיר 409. אי אפשר למחוק את המשתמש המחובר או משתמש שיש לו כתבות, ואי אפשר להוריד לעצמך את תפקיד העורך.
- **נתוני דמה**: `seed/seed.js` יוצר עורך אחד, שלושה כתבים ו-500 כתבות בכל המצבים והקטגוריות. התוכן לקוח מ-44 כתבות חדשות קצרות (`seed/newsArticles.js`) שחוזרות על עצמן, ולכן כותרות מופיעות יותר מפעם אחת, ו-`seedComments.js` מוסיף 90 תגובות ל-30 הכתבות החדשות ביותר.

### עיצוב (מערכת עיצוב משותפת)

- **קובץ אחד קובע את המראה**: `public/css/main.css` מגדיר משתנים (צבעים, רדיוסים, צללים, גופנים וצבעי מצבים: סכנה, אזהרה, נייטרלי) ורכיבים משותפים: כרטיס לבן מעוגל, כפתורי "גלולה", שדות טופס, תגיות קטגוריה, תגיות מצב (בהכנה, ממתינה, הוחזרה, פורסמה, עדכון) ומסגרת האתר (לוגו, חיפוש, ניווט). קובצי האזורים (`public.css`, `reporter.css`, `editor.css`, `users.css`) משתמשים באותם משתנים ורכיבים ומגדירים רק פריסה ייחודית לאזור, כך שדף לא יכול "לברוח" מהמראה של האתר: משנים משתנה אחד והכול מתעדכן.
- **רספונסיבי**: הפריסה מותאמת למחשב, טאבלט ונייד (בנייד הסיידבר והתוכן הופכים לעמודה אחת עם סדר קבוע). כותרת, תקציר או שם עם מילה ארוכה מאוד בלי רווחים (למשל קישור) נשברת בתוך הכרטיס ולא מרחיבה את הדף (`overflow-wrap`).
- גופנים: Heebo לטקסט ו-Playfair Display ללוגו, נטענים מ-Google Fonts (ללא אינטרנט יש גופן חלופי והאתר ממשיך לעבוד).
